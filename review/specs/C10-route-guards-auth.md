## Unit header

**Unit purpose.** Nine top-level `src/components/` files that gate access to route trees and app entry: four role/session route guards (`AuthOnlyRoute`, `ProtectedRoute`, `ClientProtectedRoute`, `ContractorProtectedRoute`), a globally-mounted auto-logout watcher (`SessionWatcher`), a contractor-blocking orphan-inspection modal (`OrphanResolutionModal`), a public-page visitor registration form (`VisitorRegistrationGate`), a first-login profile wizard (`OnboardingWizard`), and a legacy-URL slash normaliser (`DoubleSlashRedirect`).

**Module-level observations (cross-file facts inside the unit).**
- The three role guards (`ProtectedRoute`, `ClientProtectedRoute`, `ContractorProtectedRoute`) share an identical skeleton built from C02 primitives: `useAuthSession` (src/components/auth/useAuthSession.ts:14), `useUserRole` (H03, src/hooks/useUserRole.tsx:7), `useOnboardingStatus(!!session)` (src/components/auth/useOnboardingStatus.ts:10), `AuthLoading` while loading, `Navigate` to `/auth/login?next=<encoded path+search>` when no session, then children wrapped in `OnboardingGate`. Comments in C02 record this as the "EC-7" extraction (src/components/auth/useAuthSession.ts:12-13, src/components/auth/useOnboardingStatus.ts:8-9, src/components/auth/OnboardingGate.tsx:13-14).
- Guard-to-route-group mapping (grep-verified): `ProtectedRoute` → `src/app/(admin)/layout.tsx:8` (A03); `ClientProtectedRoute` → `src/app/(client-portal)/layout.tsx:5` (A06); `ContractorProtectedRoute` → `src/app/(contractor)/layout.tsx:5` (A07); `SessionWatcher` → `src/app/providers.tsx:9,23` (A01). `AuthOnlyRoute` and `DoubleSlashRedirect` have zero importers.
- None of the three role guards waits for `useOnboardingStatus` to finish loading: only `data` and `refetch` are destructured (ProtectedRoute.tsx:12, ClientProtectedRoute.tsx:14, ContractorProtectedRoute.tsx:15), and `OnboardingGate` shows the wizard only when `!!onboardingStatus && !onboarding_completed` (src/components/auth/OnboardingGate.tsx:17), so children render un-gated while the onboarding query is in flight.
- The admin-preview branches in `ClientProtectedRoute` (line 23) and `ContractorProtectedRoute` (line 22) return `<>{children}</>` directly, bypassing `OnboardingGate` (and, for contractor, `OrphanResolutionModal`).
- The working tree contains untracked Finder-style duplicates with " 2" suffixes (e.g. `src/app/providers 2.tsx`, `src/components/auth/OnboardingGate 2.tsx`, `src/views/PublicClientPortfolio 2.tsx` — all `??` in `git status`). Grep hits from those files were excluded from every "used by <-" list below.
- No test file in the repo references any of the nine files (grep over `src/**/*.test.*` for all nine names: zero hits). The nearest coverage is C02's `src/components/auth/useAuthSession.test.tsx`, which tests the shared hook, not these consumers.

**External contract.** The rest of the app gets: (1) three default-exported route-group gatekeepers that App Router layouts (A03/A06/A07) wrap around their children, each redirecting by role via the L13 navigation shim; (2) a render-nothing `SessionWatcher` mounted once in the global providers (A01) that signs everyone out at an admin-configured daily time; (3) `VisitorRegistrationGate` + `getVisitorSession` consumed by three public token pages in V04; (4) `OnboardingWizard` consumed only by C02's `OnboardingGate`; (5) `OrphanResolutionModal` consumed only inside this unit by `ContractorProtectedRoute`. `AuthOnlyRoute` and `DoubleSlashRedirect` export the same wrapper shape but are consumed by nothing.
