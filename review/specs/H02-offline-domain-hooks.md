## Unit header

**Unit purpose (as-is).** Seven React hooks that give feature views/components offline-first domain operations: CRUD on inspections and subsections, floor-plan pins/markups/measurements, a standalone offline photo capture-and-sync pipeline, camera/file-picker capture (Capacitor native + web fallback), and a general-purpose Supabase Storage image uploader. Five hooks write to IndexedDB and/or the localStorage mutation queue when offline; two (useCamera, useImageUpload) are online-oriented capture/upload utilities with no queueing.

**Module-level observations (cross-file facts).**
- Two different queue pathways coexist inside the unit: useOfflineInspections, useOfflineSubsections and useOfflineFloorPlanAnnotations enqueue via `useOfflineSync().queueMutation/queueUpload` (H01: src/hooks/useOfflineSync.ts:75, :92); useOfflineInspectionDetail bypasses H01 and calls `enqueueOfflineMutation` from src/lib/offlineQueue directly (useOfflineInspectionDetail.ts:10, :173, :197, :258); useOfflinePhotos uses neither queue — it runs its own upload loop against storage + the `offline_photos` table (useOfflinePhotos.ts:187-287).
- Three private canvas `compressImage` implementations exist in the unit, none shared: useOfflineInspectionDetail.ts:377-422 (maxWidth 800 / quality 0.7, rejects the promise on failure), useOfflinePhotos.ts:58-87 (500/0.5 "aggressive" or 800/0.7 "standard", resolves the original file on failure), useImageUpload.ts:25-86 (`COMPRESSION_CONFIG` 800/0.7, useImageUpload.ts:12-16, resolves the original file on failure).
- Two private HEIC→JPEG converters: useCamera.ts `convertHeicToJpeg` (:16-43, detects by MIME type or .heic/.heif filename, returns the original file if conversion fails) and useImageUpload.ts `convertHeicToJpg` (:91-115, detects by filename extension only, toasts and **throws** on failure). Both dynamically import `heic2any` (useCamera.ts:27, useImageUpload.ts:96; dependency `heic2any ^0.0.4`, package.json:61).
- Online-state derivation differs per file: three hooks take `isOnline` from `useOfflineSync()` (useOfflineInspections.ts:22, useOfflineSubsections.ts:32, useOfflineFloorPlanAnnotations.ts:35); useOfflineInspectionDetail keeps its own state + listeners + 15 s interval over `getOnline` from src/lib/onlineStatus (useOfflineInspectionDetail.ts:22, :35-52); useOfflinePhotos does a one-shot `getOnline()` at render (useOfflinePhotos.ts:111) and reads `navigator.onLine` directly inside sync logic (:188, :209, :320, :327).
- Shared "try online first, fall back to offline" pattern: in useOfflineInspections, useOfflineSubsections and useOfflineFloorPlanAnnotations the online branch is wrapped in try/catch whose catch only `console.error`s and falls through to the offline path — any online failure (network or server rejection) is followed by offline persistence and a success toast (e.g. useOfflineInspections.ts:44-47→60, useOfflineSubsections.ts:119-121→138, useOfflineFloorPlanAnnotations.ts:64-66→100).
- All user feedback in the unit goes through `sonner`'s `toast` (imported in 5 of 7 source files); none use the shadcn `use-toast` store (H04).

**External contract.** The rest of the app gets: `useOfflineInspections` (V01 Inspections list), `useOfflineInspectionDetail` (V01 InspectionDetail), `useOfflineSubsections` (V07 subsection-detail aggregate hook), `useOfflineFloorPlanAnnotations` (C12 InteractiveFloorPlan), `useOfflinePhotos` (C13 OfflinePhotoGallery), `useCamera` (8 consumers across C08/C09/C12/C13/C15/V01 + useOfflinePhotos in-unit), and `useImageUpload` (C12 BeforeAfterComparison, V01 InspectionDetail). Stores the unit touches: Supabase tables `inspections`, `subsections`, `subsection_documents`, `subsection_floor_plans`, `floor_plan_pins`, `offline_photos`; storage buckets `documents`, `inspection-photos`, `coc-photos`, plus caller-supplied buckets; IndexedDB via L11 modules; localStorage key `offline_mutation_queue` (via H01/L11); edge function `compress-image` (F04).
