## Unit header

**Unit purpose.** This unit is the set of view bodies mounted on the app's unauthenticated/entry surfaces: the root entry redirector (`Index`), the 404 page (`NotFound`), the legacy `/auth` email-link dispatcher (`Auth`), the PWA install page (`Install`), the popup-blocker download handoff page (`DownloadHandoff`), and five public pages driven by either a share token (`PublicClientPortfolio`, `PublicSiteReview`, `PublicSubsectionReview`) or a bare entity id from a printed QR sticker (`PublicSubsection`, `PublicSiteRegister`). All ten are default-exported React components with no props, each mounted by exactly one or two thin App Router pages (grep-verified below).

**Module-level observations (cross-file facts).**
- The three token-gated views (`PublicClientPortfolio.tsx:55`, `PublicSiteReview.tsx:137`, `PublicSubsectionReview.tsx:132`) each run `supabase.auth.signOut({ scope: 'local' }).catch(() => {}).finally(fetch...)` on mount, with the identical comment about stale sessions and custom-domain auth-bridge mismatch. The two bare-ID QR views (`PublicSubsection`, `PublicSiteRegister`) do not sign out; `PublicSubsection` is deliberately session-aware (`PublicSubsection.tsx:57-59,104-105`).
- The same visitor-gate sequence is repeated in the three token views: `validate_access_link` RPC → `setLinkId(link.link_id)` → `getVisitorSession(linkId)` sessionStorage check → render `VisitorRegistrationGate` when unregistered (`PublicClientPortfolio.tsx:70-99,180-189`; `PublicSiteReview.tsx:147-175,273-282`; `PublicSubsectionReview.tsx:142-162,302-311`).
- Every public view reads data exclusively through `get_public_*` / `validate_access_link` RPCs on the anon Supabase client (L19); none reads tables directly except `PublicSubsection`'s `qr_scans` insert (`PublicSubsection.tsx:128`) and `Index`'s `user_roles` select (`Index.tsx:20-24`).
- Snag-status normalization differs across the unit: `PublicSubsection.tsx:231-235` and `PublicSubsectionReview.tsx:252-256` lowercase the status before comparing, while `PublicSiteReview.tsx:221` uses the literal list `['Rectified', 'Closed', 'rectified']` (lowercase `'closed'` not included).
- `PublicSubsection.tsx:259-277` and `PublicSiteRegister.tsx:98-116` contain the same inline SVG "geometric pattern" hero block, both with `<pattern id="geometric">`.
- Only `Auth.tsx:1` and `DownloadHandoff.tsx:1` carry `"use client"`; the other eight files have no directive (matches inventory/10-src-views.md:142).
- No test file references any of the ten views (grep of `src --include='*.test.*' --include='*.spec.*'` for `views/<Name>`: zero hits).
- Untracked duplicate `src/views/PublicClientPortfolio 2.tsx` exists in the working tree (git status); the other nine files have no `" 2"` counterpart in this unit.

**External contract.** The rest of the app consumes this unit solely as default-export page bodies: A01 mounts `Index` (`src/app/page.tsx:2`) and `NotFound` (`src/app/not-found.tsx:3`); A08 mounts `Auth` (`src/app/auth/page.tsx:2`); A09 mounts the remaining seven across `src/app/{download,install,portfolio,public,review}` (exact paths per file below). Nothing imports named exports from these files.

## src/views/Auth.tsx

- Purpose: Backward-compatibility dispatcher at `/auth` that converts old-shape invite/recovery email links into sessions and forwards everything else to the dedicated `/auth/*` routes (design history in comments, Auth.tsx:10-32).
- Public surface: `default Auth()` — React FC, no props (Auth.tsx:34,125). Internal async helpers `handleInviteToken(accessToken: string, refreshToken: string)` (79) and `handleRecoveryToken(tokenHash: string)` (102) are not exported.
- Inputs & outputs: reads `window.location.search` (`type`, `token`) and `window.location.hash` (`access_token`, `refresh_token`) (39-44); outputs are navigations to `/auth/set-password`, `/auth/reset-password`, `/auth/forgot-password`, or `/auth/login` plus a Supabase session established via `setSession`/`verifyOtp`. No tables/buckets/localStorage touched directly (Supabase SDK session persistence is internal to L19's client).
- Dependencies: uses -> `react` (useEffect/useState), `sonner` (`toast`, Auth.tsx:4), `@/lib/navigation` `useNavigate` (L13, navigation.tsx:21), `@/integrations/supabase/client` (L19), `@/components/LoadingState` (C16, LoadingState.tsx:12). used by <- A08 auth-routes (`src/app/auth/page.tsx:2`) (grep-verified; sole importer).
- Side effects: `window.history.replaceState({}, document.title, "/auth")` scrubs tokens from the URL before the async auth call in both handlers (85, 105; "MED #6" comments 81-84, 104); network calls `supabase.auth.setSession` (86-89), `supabase.auth.verifyOtp({ token_hash, type: "recovery" })` (106-109), `supabase.auth.getSession()` (68); subscribes to `supabase.auth.onAuthStateChange` and unsubscribes in effect cleanup (60-64, 76).
- Error handling: invite branch — on `error || !data.session`, `toast.error("Invalid or expired invite link...", { duration: 6000 })` then navigate `/auth/login` (91-97); recovery branch — `toast.error("Invalid or expired reset link...", { duration: 8000 })` then navigate `/auth/forgot-password` (111-117). No try/catch around the awaits; a rejected promise from the SDK would be an unhandled rejection inside the `void`-called helpers (48, 54).
- Tests: none found (grep-verified; no test file imports `views/Auth`).
- Observed issues: in the default branch, the `onAuthStateChange` listener (60-64) and the `getSession().then` redirect to `/auth/login` (68-74) run concurrently — both can navigate. In the invite/recovery branches the effect returns before creating the subscription, so no cleanup function is returned (47-56). `data.session?.user?.user_metadata?.requires_password_change` short-circuits the default branch to `/auth/reset-password` (69-72), a case not listed in the header comment's route table (17-27).
- ASSUMED: that Supabase SDK persists the session created by `setSession`/`verifyOtp` into localStorage (SDK behavior, not visible in this file).

- Tests: none found for this view (grep-verified). `src/lib/downloadHandoff` itself has no test file; `src/lib/fileDownload.test.ts` covers the L12 sibling, not this view.
- Observed issues: `buildDirectDownloadUrl` (12-16) is a local re-implementation of `getDirectDownloadUrl` in `src/lib/fileDownload.ts:153-157` (identical body).
