## Unit header

**Unit purpose.** The Site COC tab is the admin-facing feature for a site's Certificate-of-Compliance register: it imports two Excel workbooks (DB Schedule + Verification) into `coc_db_schedule` / `coc_certificates`, accepts bulk COC/eval file uploads into `coc_file_pool` with auto-assignment, exposes manual exception resolution, and generates/saves a Site COC PDF report. It is mounted as one tab of the admin SiteDetail view (src/views/SiteDetail.tsx:30, :838, unit V01).

**Module-level observations (cross-file facts inside the unit).**
- Single entry component: `SiteCocTab` (src/views/site-coc/SiteCocTab.tsx:19) is the only file imported from outside the unit; every other file is consumed exclusively inside src/views/site-coc/ (grep-verified, see per-file "used by" lines).
- `useSiteCoc.ts` is the unit's type hub: `CocScheduleRow`, `CocCertRow`, `CocBatch`, `SubsectionOption` are re-imported type-only by all five sub-tabs (ScheduleSubTab.tsx:7, CertificatesSubTab.tsx:5, VerificationSubTab.tsx:6, ReportSubTab.tsx:15, AssignSubTab.tsx:9). These interfaces are hand-written parallels to the generated Supabase types, cast via `as unknown as` (useSiteCoc.ts:44-47).
- CertificatesSubTab and VerificationSubTab render the same data: SiteCocTab passes the one `certificates` array to both (SiteCocTab.tsx:90-91); "Verification" is a rules-matrix presentation of the same rows.
- All Supabase mutations go through the shared browser client singleton `@/integrations/supabase/client` (L19); no edge function is called anywhere in the unit (grep of supabase/ for "SiteCoc"/"site-coc" returns nothing).
- No test file anywhere in the repo imports or names any file in this unit (grep-verified: the only repo-wide hits for "site-coc"/"SiteCoc" outside src/views/site-coc/ are src/views/SiteDetail.tsx and src/lib/pdfDocumentSaver{,.test}.ts).
- Three lib sub-units back this unit: L01 (parse/normalize/ingest/reimport), L02 (coverage/rankCandidates/uploadQueue), L03 (statusDisplay/verdictMap/cocReportModel/siteCocReport/reportKpis), plus L04 (src/lib/coc pool ingestion) and L14/L16 for the report path.

**External contract.** The rest of the app gets exactly one export: `SiteCocTab({ siteId, siteName, clientName?, siteAddress?, siteKpis?, companyLogo? })`, self-contained — it fetches all its own data by `siteId`. The only other outward coupling is the report category string `getReportCategoryName("site-coc")` = "Site COC Reports" defined in L14 (src/lib/pdfDocumentSaver.ts:205) and the rows it writes/reads in `coc_db_schedule`, `coc_certificates`, `coc_import_batches`, `coc_file_pool`, `subsections`, `subsection_documents`, `site_documents`, and the `documents` storage bucket.
