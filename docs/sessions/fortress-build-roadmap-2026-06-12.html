Build Roadmap — Fortress Building Report Pack

Consolidated build specification. Turns the gap analysis + dashboard design + validated schema into a manageable, file-level, sprint-sequenced plan that reuses the existing Insight Linker engine and ships value early.

Scope locked (this session): full Fortress pack — all 17 domains incl. commercial, Excel-import-first. Buildings = existing sites. One pure KPI module per score, screen + PDF share it.

Problem & outcome

WM produces three Fortress report types per building (OPS monthly, CM monthly, Annual) by hand in Excel. The data lives nowhere queryable, KPIs are recomputed per report, and the app today only covers the electrical-compliance slice. Outcome: capture every Fortress domain once, drive a per-building dashboard + the three report packs from one data model, so a building lead sees compliance, condition, assets, utilities, tenants and incidents live, and the reports generate themselves.

MVP vs deferred

In v1 (native capture)

  • Building profile + identity header
  • Asset register + PPM
  • OHS compliance % + building condition
  • Utilities reconciliation
  • Tenant register + shop specs + compliance matrix
  • Masterfile, expense recoveries, incidents
  • Per-building dashboard (8 KPI groups) + OPS/CM/Annual PDF packs

In v1 (import-only) · deferred native

  • Trading / turnover / density / COO
  • Tenant movements, vacancy, arrears, footfall, toilet fund
  • — displayed & reported, populated from CM Page 2 import; native entry forms = V2

Not v1

  • Multi-building portfolio analytics (Sprint 5 / stretch)
  • Tenant-isolation RLS rework beyond read-scoping (G-SEC-13 track)
  • Live finance-system integration (MDA/Nimbus)

Success metric

Abaqulusi Plaza’s OPS + CM + Annual reports generate from captured data with zero manual Excel assembly, and the dashboard’s 38 KPIs match the generated PDFs exactly (screen↔PDF parity test passes). Baseline today: 0 of 3 reports automated.

2 · Tech stack — reuse, don’t reinvent

No new platform choices. Every pick is the existing app stack; the discipline is where new logic lives, not what it’s written in. Justifications trace to the builder’s skills and the existing codebase.

5 · Feature breakdown

Each MVP feature as a buildable unit: user story · acceptance criteria · complexity (S/M/L/XL) · deps.

F1 · Building profile & identity header extend S
As a building lead, I want each site to carry its property profile so the dashboard shows GLA, occupancy, managers and anchors at a glance.
  • Sites edit form captures the 13 profile fields; header renders them
  • Occupancy % = (gla−vacancy)/gla computed in a pure helper
  • Empty/legacy sites show “—”, never crash
Deps: migration applied
F2 · Excel import pipeline (framework) new L
As an admin, I want to upload a Fortress workbook and preview what will load before committing, so a template change can’t silently corrupt data.
  • Edge fn parses a sheet via a versioned column-map (not hard-coded indices)
  • Preview shows row counts, unmapped columns, arity errors; commit is blocked on errors
  • Re-run is idempotent (deterministic keys, upsert)
  • Batch recorded in fortress_import_batches
Deps: migration; blocks F3–F11 import paths
F3 · Asset register + PPM new L
As an ops manager, I want every building system as an asset with its service dates so I see what’s due, overdue and on-schedule.
  • CRUD + import for building_assets; PPM grid from ppm_tasks
  • ppm.ts returns due≤30d, overdue, on-schedule% (unit-tested)
  • Service reminders via existing calendar_events/notifications
  • Dashboard Group C cards bind to ppm.ts
Deps: F2
F4 · OHS compliance % new M
As a compliance lead, I want a weighted building OHS % separate from electrical COC.
  • buildingCompliance.ts weighted rollup with tunable weights constant
  • Hero card + Group A; bands via shared getHealthBand()
  • Per-section drill-down (occupancy, fire, critical equipment…)
Deps: F2; reuses siteHealth band helper
F5 · Building condition inspection extend M
As an inspector, I want to grade building elements Good/Fair/Poor with an action timeframe, reusing the inspection engine.
  • D4 resolved: condition + action_level captured; action items flow to snags
  • Seed Building-Condition + OPS-monthly templates
  • Group B KPIs (acceptable %, immediate/3-month counts, Poor count)
Deps: snag lifecycle migration; site-health redesign
F6 · Utilities reconciliation new M
As an ops manager, I want solar/borehole yield, water balance and night usage tracked monthly.
  • utilities.ts: yield %, water-balance variance, night-usage flag
  • Group D cards; variance >±5% flags red
Deps: F2
F7 · Tenant register + shop specs + compliance matrix new L
As a centre manager, I want every tenant with shop spec and compliance flags (evac, HVAC, COC, gas).
  • tenants backfilled from subsections.tenant_name
  • Shop-spec import; amperage actual-vs-lease over-draw flag
  • Group E compliance matrix
Deps: F2
F8 · Ledgers — masterfile · recoveries · incidents new M
As a building lead, I want masterfile completeness, expense recovery % and incident trends.
  • CRUD + import for the three ledgers; Groups G/H
  • Masterfile % and recovery-vs-budget computed in helpers
Deps: F2
F9 · Commercial import (trading/movements) import-only M
As an asset manager, I want trading/density/COO/footfall/arrears shown, imported from CM Page 2.
  • Import-only; no native entry UI v1 (Decision D5)
  • Group F tiles flagged “imported” with source period
Deps: F2
F10 · Per-building dashboard extend L
As any building user, I want one screen with hero KPIs + 8 grouped cards, each linked to its source.
  • Route /sites/[id]/fortress; cards bind only to pure KPI modules
  • Band colours consistent everywhere
Deps: F3–F9
F11 · Report pack generation (OPS/CM/Annual) extend L
As WM, I want the three reports generated from captured data, matching the dashboard exactly.
  • Three generators reuse pdfmake pipeline, fed by reportKpis.ts
  • Screen↔PDF parity test on a fixture building
Deps: F10

8 · Risks & mitigations

RiskLikelihoodImpactMitigation
Workbook layout drift breaks importsHighMedVersioned column-maps + preview/validate + reject on arity mismatch (F2); never hard-code indices
Tenant data leaks across buildings (G-SEC-13)MedHighMembership-scoped RLS (S0-5); /security-review gates apply
Screen ↔ PDF KPI driftMedHighSingle pure KPI modules; parity test (S4-4); no inline calc
Scope sprawl (full pack is large)HighMedValue-first sequencing; commercial import-only; portfolio = S5/stretch
Stale schema docs cause a bad migrationMedHighPre-audit (S0-1) gates every migration; ON CONFLICT-safe seed
Naming clash (two “Fortress”)HighLowRename electrical template in S0-3 before any UI
Offline parity for new tables underestimatedMedMedDeferred to S5; not on the v1 critical path
Load-bearing assumption: the three workbook layouts are stable enough to map once. If the client changes templates often, import-first economics weaken and native forms move earlier. Validate by diffing 2–3 months of each report before committing the column-maps.
